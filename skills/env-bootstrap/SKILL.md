# 环境自举（没有环境就自己装，不要停下来问）

## Overview
任务开始前先确认运行环境真实可用；缺什么就自己装什么、配什么，装完重探一次再继续。环境问题是可解决的工程问题，不是停工理由。

## When to Use
- 适用：缺少运行时/工具链/系统依赖（没 JDK、没 python3、没包管理器、没数据库服务、缺目录/端口）。
- 适用：探测结果可疑——`JAVA_HOME` 未设、`PATH` 里没有目标工具、只找到桩件。
- 不适用：产物里的代码依赖选型（不得引入未登记的库/框架，详见 `dev-java-springboot` 等栈规范）。
- 不适用：需要人工授权的生产环境或共享基础设施变更。

## Core Process
1. **没有环境就自己装**：需要的运行时/工具链/系统依赖不在机器上（没 JDK、没 python3、没包管理器、没数据库服务、缺目录/端口）时，由系统**自己安装并配置**好（`brew install` / `apt-get install` / 官方安装器），装完**重探一次**再继续。不要以「环境不具备」为由停下等人，也不要假装环境已就绪。
2. **先探测再安装**：`JAVA_HOME` → `PATH` → 包管理器 keg 路径逐级探测；macOS 的 `/usr/bin/javac`、`/usr/bin/python3` 是「其实没装」的桩，判定必须看真实 `-version` 输出，不能只看可执行位。
3. **安装要幂等 + 有超时**：已有的不动、只装缺的那一个；一条命令卡住要有上限，别把整条流水线挂死。
4. **配置也算环境**：`JAVA_HOME`/`PATH`、UTF-8 编码、UTC 时区、必要目录与端口，装完一并配好（keg-only 的 JDK 尤其要显式指路径）。
5. **装不上才失败，失败要可执行**：写明「试过哪条命令、退出码、还差什么、用户下一步怎么装」。**不许**用桩件、模拟数据或降级跑法把「没环境」糊过去。
6. **边界**：这里说的「自己装」指**运行环境**；产物里的代码依赖仍按架构规约（不得引入未登记的库/框架，详见 `dev-java-springboot` 等栈规范）。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 「环境没装，先问用户」 | 运行环境属于可自举范围；先探测、安装、重探。装不上才回报，并带上退出码。 |
| 「`which java` 有输出，环境就绪」 | macOS 的 `/usr/bin/javac`、`/usr/bin/python3` 是桩；必须看真实 `-version` 输出。 |
| 「先把功能写完，环境晚点再说」 | 没验证过环境就没法证明产物能跑；重探通过前不算完成。 |
| 「跑不通就 mock 掉」 | 桩件、模拟数据、降级跑法都不能替代真实环境；这是把「没环境」的失败伪装成成功。 |
| 「装完工具就算好了」 | `JAVA_HOME`/`PATH`、编码、时区、目录、端口都是环境的一部分，缺一项后面照样炸。 |

## Red Flags
- 还没探测就向用户报告「环境不具备」。
- 只看可执行位或 `which`，不看 `-version` 实际输出。
- 引入桩件、模拟数据或降级跑法绕过缺失的运行环境。
- 安装脚本重复安装已有组件，或没有超时保护。
- keg-only 的 JDK 只用 keg 路径而没显式设置 `JAVA_HOME`。

## Verification
- [ ] 目标运行时的 `-version` 真实输出（非 `which`、非可执行位）已记录。
- [ ] 缺的组件已安装，且重探一次的结果与安装前不同。
- [ ] `JAVA_HOME`/`PATH`、UTF-8、UTC 时区、必要目录与端口已配置并复验。
- [ ] 安装命令幂等（二次运行无副作用）且带超时上限。
- [ ] 若最终失败，回报含「试过的命令、退出码、还差什么、用户下一步怎么装」。
