# 配置与密钥管理

## Overview
部署阶段把配置分好类、登记清楚，启动即校验，密钥按流程轮换，配置变更走变更流程且打码留痕。配置错了是运维事故，密钥泄漏是安全事故。

## When to Use
- 适用：部署阶段涉及环境无关默认值、环境相关配置、密钥的划分与落地。
- 适用：新增/修改配置项、轮换密钥、变更生产环境配置。
- 不适用：本地开发的临时调试配置。
- 不适用：尚未进入部署阶段的纯设计讨论（先按 `security-baseline` 处理）。

## Core Process
1. 配置分三类：环境无关的默认值（进代码）、环境相关的值（环境变量/配置中心）、密钥（密钥管理服务），边界写清楚。
2. 每个配置项登记：键名、类型、默认值、是否必填、影响范围（哪些实例要一起改）、修改是否需要重启。
3. 启动即校验：缺失或格式错误的配置必须**启动失败并打印明确原因**，不允许带着空值跑。
4. 密钥轮换：周期、步骤（新老并存 → 切换 → 撤销旧值）、验证方式、责任人；轮换期间的回滚路径写清楚。
5. 配置变更走变更流程：谁改的、改了哪几个键、在哪个环境、如何验证；敏感值在记录里打码。
6. 禁止把配置与密钥提交进仓库（含示例文件里的真实值）；仓库里只放 `.example` 并注明获取方式。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 「先按默认值启动，缺了再补」 | 缺失或格式错误的配置必须启动失败并打印明确原因，不允许带着空值跑。 |
| 「只是示例文件，放真实值方便同事」 | 示例文件里的真实值同样算泄漏；仓库只放 `.example` 并注明获取方式。 |
| 「轮换密钥一次切换就行」 | 必须走新老并存 → 切换 → 撤销旧值，并写明验证方式、责任人与回滚路径。 |
| 「改个配置值而已，不用记录」 | 配置变更走变更流程：谁改的、改了哪几个键、哪个环境、如何验证，敏感值打码。 |
| 「配置项太多，登记不过来」 | 每个配置项的键名、类型、默认值、是否必填、影响范围、是否需重启都要登记；漏登记就是下次事故。 |

## Red Flags
- 应用带着空配置或错误格式的配置正常启动，只在运行时报错。
- 仓库或示例文件里出现真实密钥/令牌。
- 密钥轮换只做了一次切换，没有并存期、没有撤销旧值、没有回滚路径。
- 配置变更没有记录，或记录里含未打码的敏感值。
- 配置项没有登记影响范围，改一个键时其他实例静默失效。

## Verification
- [ ] 三类配置的存放边界已写明，落地位置与描述一致。
- [ ] 配置清单含键名、类型、默认值、是否必填、影响范围、是否需重启。
- [ ] 故意删掉一个必填配置后，进程启动失败且打印了明确原因（贴出实际输出）。
- [ ] 密钥轮换文档含周期、并存→切换→撤销步骤、验证方式、责任人与回滚路径。
- [ ] 仓库与示例文件中扫描不到真实值，只存在 `.example` 且注明获取方式。
- [ ] 变更记录可回答「谁、何时、改了哪几个键、哪个环境、如何验证」，敏感值已打码。
