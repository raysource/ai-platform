# 可访问性与文案

## Overview
界面可访问性按 `WCAG AA` 执行，文案规范统一、术语一致、可翻译。这两条是交互设计的底线，缺一项交付就不可用。

## When to Use
- 适用：UX 阶段——设计或评审界面可访问性与文案时。
- 不适用：后端接口与数据建模；与用户界面无关的演示图形。

## Core Process

### 对比度与信息载体
- 底线按 `WCAG AA` 执行：正文对比度 `≥4.5:1`（大字 `≥3:1`），颜色不作为唯一信息载体（错误同时给图标/文字）。

### 键盘可达
- 键盘可达：所有可操作元素可 `Tab` 到、焦点可见（有 `focus` 样式）、弹层内焦点被限制且 `Esc` 可关闭。

### 表单可访问
- 表单可访问：每个输入有 `label`（不是 `placeholder` 顶替）、错误用 `aria-describedby` 关联、必填有文字标识。

### 语义与顺序
- 语义与顺序：标题层级不跳级、按钮用 `button` 不用可点击 `div`、图片有 `alt`（装饰图空 `alt`）。

### 文案规范
- 文案规范：动作用动词（保存 / 提交 / 删除），不用「确定/是/否」这类无信息词；术语与架构文档一致，全文统一。

### 长度与截断
- 长度与截断：列表项给最大长度与截断规则（省略号 + `title` 全文），中英文混排不靠字数估宽。

### 可翻译
- 文案要能被翻译：不要拼字符串（`已选 {n} 项` 用占位符），避免仅靠语序表达逻辑。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 可访问性以后再补 | 底线是 `WCAG AA`，对比度、键盘可达、表单关联都必须当场满足。 |
| placeholder 能当 label | 表单必须每个输入有 `label`，不能用 `placeholder` 顶替。 |
| 用颜色标错误就够了 | 颜色不作为唯一信息载体，错误要同时给图标/文字。 |
| 文案回头再润色 | 动作用动词、术语与架构文档一致，且要能翻译（用占位符，不拼字符串）。 |
| 截断就按字数估 | 中英文混排不靠字数估宽，要给最大长度与省略号 + `title` 规则。 |

## Red Flags
- 对比度未达 `4.5:1`，或用颜色单独表达状态。
- 可操作元素 `Tab` 不到、焦点不可见、弹层 `Esc` 关不掉。
- 输入用 `placeholder` 顶替 `label`、必填无文字标识。
- 文案出现「确定/是/否」或拼字符串（非占位符）。
- 标题跳级、用可点击 `div` 当按钮、图片缺 `alt`。

## Verification
- [ ] 正文对比度 `≥4.5:1`（大字 `≥3:1`），颜色非唯一信息载体。
- [ ] 所有可操作元素可 `Tab` 到、有 `focus` 样式、弹层焦点受限且 `Esc` 可关。
- [ ] 每个输入有 `label`，错误用 `aria-describedby` 关联，必填有文字标识。
- [ ] 标题不跳级、按钮用 `button`、图片有 `alt`（装饰图空 `alt`）。
- [ ] 文案用动词、术语与架构文档一致；插值用占位符（如 `已选 {n} 项`）。
- [ ] 列表项给出最大长度与截断规则（省略号 + `title`）。
