# WBS 估算与依赖

## Overview
为已拆好的 WBS 任务补齐三点估算、关键路径、独立缓冲、外部依赖与里程碑判据，让总工期、风险来源与并行机会都可见、可核算，而不是藏在一个无法验证的日期里。

## When to Use
- 适用：给 WBS Task 估工时；标定关键路径与非关键路径的可并行度；设置总缓冲与消耗规则；登记外部依赖；编写里程碑进入/退出条件。
- 不适用：任务粒度拆分与验收判据定义——这些走 `wbs-module-granularity`。

## Core Process
- 估算给三点值（乐观/最可能/悲观）与依据（参照哪个类似模块、复杂度来自哪里），禁止只给一个数字。
- 关键路径显式标出：哪些 Task 串行决定总工期；非关键路径给出可并行度与插入条件。
- 缓冲单独列（不要藏进每个任务里）：总缓冲 = 关键路径的 15–25%，并写明消耗规则。
- 外部依赖单列：依赖谁、需要什么前置物、最晚确认时间、未满足时的临时降级方案。
- 排期用「相对周次 + 里程碑判据」表达（第 1 周结束：需求全部批准），不要写没有判据的日期。
- 每个里程碑写明进入条件与退出条件（哪些产物已被人工批准、哪些测试已全绿）。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 「估一个最可能的数就行」 | 单个数字把风险抹平，读图的人无法判断工期下限与上限，也无法据此设缓冲。 |
| 「缓冲平摊进每个任务更安全」 | 摊进去后没人知道剩余缓冲有多少，关键路径一超期就无缓冲可用；缓冲必须单列并写消耗规则。 |
| 「外部依赖到时候去问」 | 不写最晚确认时间与降级方案，依赖一旦延迟直接击穿关键路径，没有退路。 |
| 「排期给具体日期更清楚」 | 无判据的日期不可验证，会随实际进度漂移；应给相对周次 + 里程碑判据。 |

## Red Flags
- 任务只给一个数字工时，没有乐观/最可能/悲观与依据。
- 缓冲被摊进各任务，总缓冲量不可见。
- 关键路径未标出，或非关键路径没写可并行度。
- 外部依赖缺最晚确认时间或降级方案。
- 里程碑只有日期，没有进入/退出条件。

## Verification
- [ ] 每个 Task 都有三点估算及依据（参照的类似模块、复杂度来源）。
- [ ] 关键路径已显式标出，非关键路径给出可并行度与插入条件。
- [ ] 缓冲单列，总量为关键路径的 15–25%，且写明消耗规则。
- [ ] 外部依赖列出依赖对象、前置物、最晚确认时间与降级方案。
- [ ] 排期用相对周次 + 里程碑判据表达，每个里程碑写明进入与退出条件。
