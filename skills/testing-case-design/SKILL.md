# 用例设计方法（等价类 / 边界 / 状态机）

## Overview
这套方法把「该测哪些用例」从拍脑袋变成可复算的推导：先按输入维度划分等价类与边界值，再用两两组合压住组合爆炸，用状态×事件表压住状态机需求，最后把异常路径、数据清理与风险等级补齐，让用例既完整又可重复执行、可分级退出。

## When to Use
- 适用：为某需求/接口/模块设计测试用例；输入有明确取值范围或校验规则；存在多参数组合；有状态流转（订单、审批、任务）；需要补异常路径与并发/重复提交场景。
- 不适用：统计需求×用例覆盖矩阵与出口标准（用 `testing-coverage-matrix`）；性能压测与安全用例设计（用 `testing-perf-and-security`）；只做评审代码而不写用例（用 `development-review-checklist`）。

## Core Process
1. 每个输入维度列等价类（有效/无效）并各取代表值；再从每个等价类边界取 上界-1 / 上界 / 上界+1 三个值。
2. 组合爆炸用两两组合（pairwise）覆盖，而不是全排列；写清哪些组合被有意排除及理由。
3. 状态机类需求：画状态×事件表，覆盖合法迁移 + 非法迁移（非法迁移必须被拒绝且状态不变）。
4. 异常路径与正常路径同等对待：超时、重复提交、并发写、外部依赖失败（超时/错误码/空响应）都要有对应用例。
5. 数据相关用例写明数据来源与清理（谁造的、跑完留不留），确保重复执行结果一致。
6. 每个用例标注风险等级（P0 阻塞主流程 / P1 影响体验 / P2 边界），退出标准按等级区分。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 等价类就是随便挑几个值试试 | 等价类是「同一类内等价、跨类不等价」的划分，漏掉一个无效类就等于漏掉一类缺陷；每类必须有代表值证据。 |
| 组合太多，全排列跑不完就先挑常走的路径 | 该做的是两两组合覆盖并显式写明排除项与理由，而不是只测主路径；未覆盖的组合一旦是缺陷入口就没人发现。 |
| 状态机只测合法迁移就够了 | 非法迁移（越权状态跳转、重复取消）常是数据错乱来源，必须断言被拒绝且状态不变。 |
| 异常路径属于「偶发」，等真出问题再补 | 超时、重复提交、并发写是必现的常规场景，事后补用例等于把首次暴露点留给生产。 |
| 测试数据随便造，跑完不管 | 数据来源与清理不写清，用例不可重复执行，第二次跑的结果不可信。 |

## Red Flags
- 用例只有正常路径，异常路径、错误码、超时场景为空。
- 边界只取了上界/下界本身，没取 上界-1 与 上界+1。
- 多参数场景全部按全排列写，或只用「代表性组合」却不写排除理由。
- 状态机需求没有状态×事件表，或表里没有非法迁移行。
- 用例没有风险等级标注，退出标准对所有用例一刀切。

## Verification
- [ ] 每个输入维度的有效/无效等价类都有对应用例编号，且每类至少一个代表值。
- [ ] 每个等价类边界都有 上界-1 / 上界 / 上界+1 三个值，边界用例可列出。
- [ ] 组合场景标明覆盖方式为 pairwise，且附有意排除组合及理由。
- [ ] 状态×事件表存在，合法迁移与非法迁移均有用例，非法迁移断言「被拒绝且状态不变」。
- [ ] 异常路径用例覆盖超时、重复提交、并发写、外部依赖失败四类。
- [ ] 每条数据相关用例写明数据来源与清理方式，且有风险等级（P0/P1/P2）标注。
