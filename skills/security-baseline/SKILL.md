# 通用安全与合规底线（所有阶段适用）

## Overview
这是一条贯穿所有阶段、不随技术栈变化的底线：默认拒绝、永不信任输入、最小权限、数据最小化、密钥不进代码。任何阶段交付前都要用它自查一次。

## When to Use
- 适用：设计、实现、评审、交付任何一个阶段的产物。
- 适用：涉及权限判断、外部输入、数据库账号、令牌、日志与导出文件的改动。
- 不适用：某个具体框架/中间件的专门加固细节（另按对应栈规范处理）。
- 不适用：与本仓库产物无关的第三方系统运维。

## Core Process
1. 默认拒绝：未明确授权的访问一律拒绝；权限判断在服务端，前端隐藏按钮不算权限控制。
2. 永不信任输入：所有来自用户/第三方/文件/URL 的数据在入口校验（类型/长度/范围/白名单），并在使用处再确认一次边界。
3. 最小权限：进程、数据库账号、服务账号、令牌都只给完成任务所需的最小范围；不用管理员账号跑应用。
4. 数据最小化：只收集必须的数据，明确用途与留存期；日志、错误页、导出文件都不含密码/令牌/身份证等敏感字段。
5. 密钥不进代码与镜像：只从环境变量或密钥服务读取；发现泄露立即轮换并记录。
6. 依赖与供应链：锁定版本、定期扫描已知漏洞、禁止来源不明的包与构建脚本（`postinstall` 之类）。
7. 可追溯：关键变更（权限、配置、数据删除、发布）都有审计记录，能回答「谁在什么时候改了什么」。
8. 每个阶段交付前自问一次：这份交付物泄漏或出错时，最坏后果是什么？对应的防护写在交付物里。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 「前端已经把按钮藏了」 | 前端隐藏不是权限控制；判断必须在服务端，未授权请求要真正被拒绝。 |
| 「输入是内部服务给的，不用校验」 | 入口一律校验，不问来源；使用处还要再确认一次边界。 |
| 「先用管理员账号跑起来，后面再收权限」 | 最小权限是交付前提；用管理员账号跑应用本身就是漏洞。 |
| 「日志里不记敏感字段就不好排查」 | 日志、错误页、导出文件都不含密码/令牌/身份证；排查用打码或关联 ID。 |
| 「密钥先写进配置，方便本地跑」 | 密钥只从环境变量或密钥服务读取；进了代码/镜像就要按泄露流程轮换。 |

## Red Flags
- 权限判断只在前端，或服务端默认放行。
- 外部数据未经校验就直接进业务逻辑或查询。
- 应用/账号/令牌使用超出任务所需的范围，甚至用管理员账号。
- 代码、镜像、示例文件里出现真实密钥或敏感字段。
- 依赖版本未锁定，或存在来源不明的包与构建脚本（`postinstall` 之类）。

## Verification
- [ ] 未授权请求的实际响应为拒绝（有可复现的请求/响应证据）。
- [ ] 每个入口都有类型/长度/范围/白名单校验，使用处有二次边界确认。
- [ ] 运行所需账号与令牌已收敛到最小范围，未使用管理员账号。
- [ ] 遍历日志、错误页、导出文件，确认无密码/令牌/身份证等敏感字段。
- [ ] 仓库与镜像中扫描不到真实密钥；依赖版本已锁定并可扫描已知漏洞。
- [ ] 权限、配置、数据删除、发布等关键变更留有审计记录。
