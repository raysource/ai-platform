# 性能与安全测试

## Overview
压测的价值不在「跑过」，而在「在明确目标下得到可复现的数字并定位瓶颈」；安全测试的价值不在「扫过」，而在「每个失败项都有复现步骤、影响面、修复建议且回归转绿」。本技能给出两者的目标定义、执行模型、记录要求与判定标准。

## When to Use
- 适用：性能验收、容量摸底、压测瓶颈定位、安全测试（越权/注入/弱口令/信息泄露/上传穿越）及安全回归验证。
- 不适用：功能测试用例设计（用 `testing-case-design`）；覆盖矩阵与出口标准（用 `testing-coverage-matrix`）；上线后的持续监控、告警阈值与成本容量规划（用 `operations-monitoring-runbook`、`operations-cost-and-capacity`）。

## Core Process
1. 压测先定目标：并发数、持续时间、期望 P95/P99 与错误率阈值、允许的降级行为；没有目标数字就不开跑。
2. 压测模型要接近真实：读写比例、数据分布、登录/会话开销、峰值突增（阶梯加压 + 尖峰两轮）。
3. 记录必须可复现：脚本、参数、数据量、环境规格、被测版本号；结论写「在什么条件下得到什么数」。
4. 观测压测中的四类指标（吞吐/错误/延迟/资源），给出瓶颈定位（DB 慢查询、连接池、GC、锁等待）与结论动作。
5. 安全用例至少覆盖：越权（水平/垂直）、注入（SQL/命令/模板）、弱口令与暴力破解、敏感信息泄露（错误页/日志/导出）、上传与路径穿越。
6. 每个失败项给复现步骤、影响面与修复建议，并回归验证（同一用例必须转绿）。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 先把脚本跑起来，看个大概数再定目标 | 没有并发/时长/P95/错误率阈值，跑出来的数字无法判断通过与否，等同于没测；目标必须写在压测前。 |
| 环境差一点没关系，相对趋势差不多 | 环境规格未记录的数不可复现也不可对比；记录必须写明环境、数据量、版本号，结论限定条件表述。 |
| 只看平均响应时间就够了 | 平均值掩盖长尾，P95/P99 才是用户体验与超时的判据；四类指标必须一起观测才能定位瓶颈。 |
| 安全测试用工具扫一遍出报告就行 | 自动化扫描覆盖不到越权与业务逻辑泄漏；失败项需人工复现步骤、影响面与修复建议，且回归必须转绿。 |
| 这次先记下问题，回归以后再说 | 不回归等于漏洞仍在；同一用例必须复跑转绿才算闭环。 |

## Red Flags
- 压测已开始但目标数字（并发/时长/P95/P99/错误率）缺失或事后补写。
- 压测记录缺少脚本、参数、数据量、环境规格或被测版本号中的任意一项。
- 只报平均值/吞吐，没有延迟分位数与错误率、资源曲线。
- 结论只写「性能不错/偏慢」，没有瓶颈定位（DB 慢查询、连接池、GC、锁等待）与后续动作。
- 安全用例未覆盖越权、注入、弱口令、泄露、上传穿越中的任一类。
- 失败的安全项只有结论没有复现步骤，或回归验证未执行。

## Verification
- [ ] 压测目标（并发数、持续时间、P95/P99、错误率阈值、允许降级行为）在开跑前已成文。
- [ ] 压测模型说明了读写比例、数据分布、登录/会话开销，且包含阶梯加压与尖峰两轮。
- [ ] 记录含脚本、参数、数据量、环境规格、被测版本号，结论以「条件下得到什么数」表述。
- [ ] 四类指标（吞吐/错误/延迟/资源）均有观测数据，并给出瓶颈定位与结论动作。
- [ ] 安全用例清单覆盖越权、注入、弱口令与暴力破解、敏感信息泄露、上传与路径穿越五类。
- [ ] 每个失败项有复现步骤、影响面、修复建议，且回归用例已复跑转绿（附结果）。
