# 信息架构与四态

## Overview
UI/UX 交付要有结构而不是风格描述：信息架构按页面层级编号、每个界面写全四态、交互规则写到前端可实现粒度。这样交付物才能被实现与评审，而不是停留在感觉上。

## When to Use
- 适用：UX 阶段——编写或评审信息架构、界面四态与交互规则时。
- 不适用：视觉风格稿与品牌调性讨论。

## Core Process

### 信息架构
- 信息架构用「页面/区域/控件」三级列表写，每级给稳定编号（`IA-NN`），标出主路径与异常路径。

### 四态
- 每个界面写四态：空、加载、成功、失败（含失败提示文案与下一步动作），禁止只画成功态。

### 交互规则
- 交互规则写在前端可实现的粒度：字段校验时机（失焦/提交）、按钮禁用条件、错误如何回填到字段。

### 文案
- 文案必须给最终中文（不用「这里放提示」占位），长度上限与截断规则一并写明。

### 可访问性底线
- 可访问性底线：键盘可达、焦点可见、表单控件有 `label`、颜色不作为唯一信息载体。

## Common Rationalizations
| 借口 | 事实 |
|---|---|
| 先把成功态画出来，其余以后补 | 每个界面必须写全空、加载、成功、失败四态，禁止只画成功态。 |
| 用风格描述示意即可 | 信息架构要用「页面/区域/控件」三级列表并给稳定编号 `IA-NN`。 |
| 交互规则等前端自己定 | 交互规则要写到前端可实现粒度：校验时机、按钮禁用条件、错误回填字段。 |
| 文案放个占位提示就行 | 文案必须给最终中文，并写明长度上限与截断规则。 |
| 可访问性交给前端 | 键盘可达、焦点可见、控件有 `label`、颜色非唯一载体是交付底线。 |

## Red Flags
- 只有成功态、没有空/加载/失败态。
- 信息架构缺 `IA-NN` 编号或未标主路径与异常路径。
- 交互规则停留在风格描述、未到前端可实现粒度。
- 文案出现「这里放提示」占位。
- 可访问性底线缺失（不可键盘达、焦点不可见、控件无 `label`、颜色作唯一载体）。

## Verification
- [ ] 信息架构为「页面/区域/控件」三级列表，每级有 `IA-NN` 编号并标出主路径与异常路径。
- [ ] 每个界面写全空、加载、成功、失败四态，失败态含提示文案与下一步动作。
- [ ] 交互规则写到前端可实现粒度：校验时机（失焦/提交）、按钮禁用条件、错误回填字段。
- [ ] 文案给出最终中文（无占位），并写明长度上限与截断规则。
- [ ] 可访问性底线满足：键盘可达、焦点可见、控件有 `label`、颜色非唯一载体。
- [ ] 产物文件落盘、事件流可见 UX 阶段产出记录。
